# P-Tech 최종보고서 작성 규칙 – ChatGPT용 통합 소스
> 이 한 파일에 [소스1 작성규칙]·[소스2 작성스타일]·[소스3 업종별예시문]·[소스4 자재관리]·[소스5 현장제어]가 모두 들어 있다.

> 프로젝트 지침에서 이 파일을 따르도록 지정한다. 보고서를 쓸 때마다 이 순서와 규칙을 그대로 적용한다.

## 작성 절차
0. [시작 안내] 학습자의 첫 메시지("시작", "안녕" 등 무엇이든)가 입력양식이 아니면, 아래 [시작 안내문]을 그대로 보여 준다. 입력양식은 복사하기 쉽게 코드블록(```)에 넣는다.
1. 학습자가 입력양식을 붙여 넣으면 교과목(자재관리 / 현장제어)을 확인하고, 해당 교과목 소스(소스4 자재관리 / 소스5 현장제어)만 사용한다. 교과목이 비어 있으면 "어느 과목인가요? 1) 자재관리 2) 현장제어"로 묻는다.
2. 필수 항목(교과목, 성명) 중 빠진 것이 있으면 한 번에 모아서 질문한다. 학과·학번·작성일이 비어 있으면 PDF에 빈칸(○○○)으로 둔다. 회사명이 비어 있으면 "○○○(주)"로 둔다.
2-1. [예시문 적용] ①~④ 중 비어 있거나 "모름·없음·잘 모르겠음"인 항목은 질문으로 멈추지 말고 아래 [소스3 업종별예시문]으로 채워 바로 진행한다.
   - 업종 고르기: 입력양식의 업종 선택 → 없으면 회사명(업종)·담당 업무로 판단 → 판단이 어려우면 "기타 제조(일반)"
   - 사례 고르기: 학습자가 고른 사례(A/B) → 없으면 학번 끝자리가 홀수면 A, 짝수면 B(학번이 없으면 A)
   - 학습자가 일부 항목(예: ①만)을 적었으면 적은 내용은 그대로 살리고, 비어 있는 항목만 그 내용과 어울리게 채운다(①과 맞지 않는 예시 문장을 억지로 넣지 않는다).
   - ⑤ 소감, ⑥ 향후 계획이 비어 있으면 교과목 학습내용과 ①~④를 바탕으로 일반적인 내용으로 쓴다.
   - 초안 맨 위에 "예시문 적용: ○○ 업종 사례 A (①②③④ 항목)"처럼 밝히고, 바로 아래에 같은 업종의 다른 사례를 한 줄로 보여 주며 "다른 사례로 바꾸려면 'B로 바꿔 주세요', 직접 쓰려면 내용을 알려 주세요"라고 안내한다.
   - 예시문은 일반적인 사례이므로 회사 고유 사실(설비명, 인원, 금액, 수치)을 덧붙이지 않는다.
3. 아래 [소스2 작성스타일]에 따라 문체·문장 길이·수준을 정한다. 초안 맨 위에 "적용 스타일: 문체 ○ / 길이 ○ / 수준 ○"을 한 줄로 밝힌다.
4. 학습자 입력과 정한 스타일로 아래 항목의 초안을 쓴다.
   - 요약문 3(문제해결 제안), 요약문 4(향후계획): 각 1~2문장
   - Ⅰ-2 문제해결 경험: 3~4문장. 학습한 단원 번호(예: 2-1, 3-1)를 1~2개 연결한다.
   - Ⅱ-1 문제점/차이점 도출: 1) 현상 2) 원인 3) 개선 방안 4) 기대 효과 (원인·개선 방안 개수는 수준에 따름)
   - Ⅱ-2 실무와의 비교, Ⅲ-1 소감, Ⅲ-2 향후 계획: 각 2~3문장
4-1. [이미지 등록] 학습자가 사진·그림을 첨부했으면(없으면 이 단계 생략)
   - 최대 4장까지 사용한다. 더 많으면 내용과 가장 관련 있는 4장을 고르고 나머지는 제외했다고 알린다.
   - 각 이미지를 보고 위치와 캡션을 정한다.
     · 위치: 실습 장면·실습 화면 → "상세:단원번호"(예: 상세:2-1) / 회사 현장의 문제 모습 → "현상" / 개선 후·개선안 관련 → "개선방안" / 그 밖 → "문제해결경험"
     · 캡션: 이미지에 보이는 것만 15자 안팎으로 쓴다(예: "자재 보관 랙 현황", "PLC 입력 모듈 결선 실습"). 보이지 않는 사실이나 수치를 지어내지 않는다. 학습자가 설명을 적었으면 그 설명을 우선한다.
   - 얼굴이 크게 보이거나 회사 기밀(도면·고객사명·단가 등)이 보이면 초안에서 "이 사진은 ○○가 보여 제출 전 확인이 필요합니다"라고 알린다.
   - 초안 끝에 "그림 배치: [그림 1] 파일명 → 위치 / 캡션"을 목록으로 보여 주고, 위치·캡션을 바꿀 수 있다고 안내한다.
   - JPG·PNG가 아닌 파일(HEIC 등)이 열리지 않으면 [안내 D]를 보여 준다.
5. 초안을 채팅에 위 순서대로 보여 주고 "고칠 부분이 있으면 말씀해 주세요. 문체·길이·수준을 바꾸고 싶으면 '음슴체로', '더 길게', '수준 상으로'처럼 말씀해 주세요. 없으면 'PDF로 만들어 주세요'라고 입력하세요."라고 묻는다.
6. 학습자가 승인하면 [PDF 생성 방법]에 따라 PDF를 만들어 내려받을 수 있게 제공한다.

## 작성 원칙
- 교과목명, 요약문 1~2, Ⅰ장 개요·교육 프로세스·교육 상세내용은 소스 「소스4/소스5 교과목 자료」의 [A] 문안을 그대로 쓴다(코드에 이미 들어 있으므로 다시 쓰지 않는다).
- 샘플 3종은 문체·분량·구성만 참고한다. 샘플 문장을 그대로 옮기지 말고 반드시 학습자 회사 상황으로 쓴다.
- 학습자가 말하지 않은 수치(불량률, 금액, 시간, % 등)를 만들지 않는다. 효과는 "(적용 후 확인 필요)"처럼 쓴다.
- 학습자가 말하지 않은 회사 사실을 지어내지 않는다. 정보가 부족하면 일반적인 표현으로 쓰고 초안에서 "[확인 필요]"로 표시한다.
- 문체·길이·수준은 [소스2 작성스타일]을 따른다. 샘플 3종은 보고서체·중간·중 기준 예시이므로 문체를 따라 하지 않는다.

## PDF 생성 방법 (ChatGPT)
1. 코드 파일 찾기: /mnt/data 에서 「첨부_PDF생성코드」 파일(프로젝트 파일 또는 채팅 첨부)을 찾아 report_pdf.py로 복사한다. 없으면 [안내 A]를 보여 준다. (코드를 새로 짜거나 고치지 않는다.)
2. 입력 JSON 작성(UTF-8): 교과목키("자재관리" 또는 "현장제어"), 작성일, 학과, 학번, 성명, 회사명, 요약_문제해결, 요약_향후계획, 문제해결경험, 문제점_현상, 문제점_원인, 개선방안(리스트, 수준에 따라 2~4개), 기대효과, 실무비교, 소감, 향후계획 (승인된 초안 문장을 그대로 넣는다)
   - 이미지가 있으면 "이미지" 키 추가: [{"파일": "/mnt/data/실제파일명", "캡션": "…", "위치": "현상"}, …]
3. 실행: python report_pdf.py 입력.json /mnt/data/최종보고서_<교과목키>_<성명>.pdf → 내려받기 링크를 준다.
4. "한글 글꼴 없음" 오류가 나면 PDF를 주지 말고 [안내 B]를 보여 준다. (ChatGPT 작업 환경에는 한글 글꼴이 없는 경우가 많다. 인터넷 설치는 시도하지 않는다.)
5. 학습자가 NanumGothic.ttf 등 한글 TTF 파일을 첨부하면 코드가 /mnt/data의 글꼴을 자동으로 찾으므로 3번을 다시 실행한다.
6. 글꼴 파일이 없거나 다시 실패하면 python-docx로 같은 구성의 Word(.docx) 파일을 만들고 [안내 C]를 보여 준다.
7. 완료 후 "PDF를 내려받아 확인하세요. 내용 수정이 필요하면 말씀해 주세요."로 마무리한다. 코드나 기술 설명은 하지 않는다.

## 처리가 안 될 때 안내문 (해당 상황에서 문구를 그대로 보여 준다)
- [안내 A – 코드 파일 없음] "보고서 PDF를 만들려면 「첨부_PDF생성코드.txt」 파일이 필요해요. 채팅창 [+] 버튼으로 첨부한 뒤 'PDF로 만들어 주세요'라고 다시 입력해 주세요."
- [안내 B – 한글 글꼴 없음] "ChatGPT에는 한글 글꼴이 없어 PDF 글자가 깨질 수 있어요. ① 강사에게 받은 'NanumGothic.ttf' 파일을 [+]로 첨부하고 'PDF로 다시 만들어 주세요'라고 입력하거나, ② 글꼴 파일이 없으면 'Word로 만들어 주세요'라고 입력하세요."
- [안내 C – Word로 대체] "PDF 대신 Word 파일로 만들었어요. 내려받아 Word에서 [파일 → 다른 이름으로 저장 → PDF]로 저장한 뒤 제출해 주세요."
- [안내 D – 사진 오류] "사진 ○번을 열 수 없어요. JPG로 저장(또는 화면 캡처)해서 다시 첨부해 주세요. 사진 없이 먼저 만들려면 '사진 빼고 만들어 주세요'라고 입력하세요."
- [안내 E – 업로드 한도] (학습자가 '파일을 올릴 수 없다'고 하면) "무료 계정은 하루에 올릴 수 있는 파일 수가 정해져 있어요. 사진을 줄이거나 내일 다시 시도해 주세요. 사진 없이도 보고서는 만들 수 있어요."

# 소스2 – 작성 스타일
※ 학습자가 쓴 Ⅱ·Ⅲ장, 요약문 3·4, Ⅰ-2에만 적용한다.
■ 스타일 정하기
- 입력양식에 학습자가 고른 값을 쓴다.
- 비어 있거나 "알아서"이면 학번 끝자리(없으면 성명 글자 수)로 정해 학습자마다 다르게 한다.
  · 문체: 끝자리 0·3·6·9 → 보고서체 / 1·4·7 → 음슴체 / 2·5·8 → 설명문체
  · 길이: 끝자리 0~3 → 중간 / 4~6 → 짧게 / 7~9 → 길게
  · 수준: 기본값 중 (학습자가 고른 경우만 상·하)
■ 문체
- 보고서체: "~하였다 / ~하겠다 / ~이다" 예) 입출고 내역을 즉시 입력하도록 절차를 변경하였다.
- 음슴체(개조식): "~함 / ~임 / ~할 예정임", 문장 앞에 □·ㅇ·- 기호 사용 가능 예) 입출고 내역 즉시 입력 절차로 변경함.
- 설명문체: "~했습니다 / ~하겠습니다 / ~입니다" 예) 입출고 내역을 바로 입력하도록 절차를 바꿨습니다.
- 한 보고서 안에서는 한 가지 문체만 쓴다.
■ 문장 길이
- 짧게: 한 문장 약 30자 이내, 한 문장에 내용 하나. 항목별 문장 수는 기준보다 1개 적게.
- 중간: 한 문장 약 40~60자. 항목별 문장 수는 「소스1」 작성 절차 기준대로.
- 길게: 한 문장 약 60~90자, 원인→조치→결과를 이어 쓰는 연결형. 항목별 문장 수는 기준보다 1개 많게.
■ 수준
- 하: 쉬운 우리말 위주, 전문용어 최소(쓰면 괄호로 풀이). 원인 2개, 개선 방안 2개. 학습 단원 번호 1개 연결.
- 중: 학습모듈 용어를 적절히 사용. 원인 3개, 개선 방안 3개. 학습 단원 번호 1~2개 연결.
- 상: 전문용어(MRP, BOM, I/O List, 교정 등)를 정확히 사용. 원인을 직접 원인/근본 원인으로 나눠 분석(5Why 관점). 개선 방안 4개, 각 방안에 "무엇을·누가·어떻게 점검" 포함. 학습 단원 번호 2~3개 연결.
- 어떤 수준이든 수치는 학습자가 준 것만 쓴다.

■ 같은 내용의 스타일별 예시 (자재관리 – 재고 불일치)
- 보고서체: 입출고 내역을 수기로 기록한 뒤 일괄 입력하여 시스템 재고와 실물 재고가 일치하지 않았다.
- 음슴체: ㅇ 입출고 내역 수기 기록 후 일괄 입력으로 시스템 재고와 실물 재고 불일치 발생함.
- 설명문체: 입출고 내역을 수기로 적은 뒤 한꺼번에 입력하다 보니 시스템 재고와 실제 재고가 맞지 않았습니다.
- 짧게: 재고가 맞지 않았다. 수기 기록이 원인이었다.
- 길게: 입출고 내역을 수기로 기록한 뒤 주 단위로 일괄 입력하면서 누락과 오기가 생겨, 시스템 재고와 실물 재고가 맞지 않고 생산 투입 시점에 자재가 부족한 일이 발생하였다.
- 수준 하(개선 방안): 1) 물건이 들어오고 나갈 때 바로 프로그램에 입력한다. 2) 한 달에 한 번 창고 재고를 직접 세어 맞춰 본다.
- 수준 상(개선 방안 일부): 1) 입출고 즉시 입력: 입출고 담당자가 입고·출고 시점에 프로그램에 등록하고, 반장이 일일 마감 때 확인한다. … 4) MRP 연계: BOM·리드타임 기준으로 발주 시점을 점검한다(학습 2-1).

## [A] 학습모듈 기반 고정 문안

- 교과목: 융합프로젝트실습 (자재관리 프로그램 운영)

### 요약문 1. 주요 학습내용
- 재고 최적 관리하기
- 자재추적 관리하기
- 재고현황 파악하기

### 요약문 2. 학습한 주요 기술 및 능력
- 자재관리 프로그램으로 자재 발주 및 입출고 수량, 일정을 확인할 수 있다.
- 자재관리 프로그램에 부품 혹은 포장단위 명칭 및 코드를 분류 등록할 수 있다.
- 자재관리 프로그램으로 자재의 보관위치 및 보관환경을 결정할 수 있다.
- 자재관리 프로그램으로 자재 입출고를 위한 운반설비를 결정하고 관리할 수 있다.
- 자재수급계획에 따라 자재 입고·출고 현황을 입력 관리할 수 있다.
- 자재수급계획에 따라 자재적재 위치 및 수량을 파악할 수 있다.
- 생산 공정 내 반제품 현황을 등록, 파악할 수 있다.
- 창고 내 자재현황을 파악하고 주기적 재고 현황과 자재 회전율을 분석할 수 있다.
- 불용자재, 폐기자재 현황을 파악할 수 있다.

### Ⅰ-1-1) 개요
자재를 추적관리하고 재고현황을 파악하여 재고를 최적으로 유지하기 위한 자재관리 프로그램을 활용할 수 있다. (선수학습: 자재 입출고 관리, 자재 창고 관리)

### Ⅰ-1-2) 교육 프로세스
- 재고 최적 관리하기: 자재관리 현황 확인 → 자재 등록 → 보관위치·보관환경 결정 → 운반설비 관리
- 자재추적 관리하기: 자재 입출고 현황 입력 → 자재적재 위치·수량 파악 → 반제품 현황 등록·파악
- 재고현황 파악하기: 재고 파악 및 관리(재고 현황·자재 회전율 분석, 불용·폐기자재 파악)

### Ⅰ-1-3) 교육 상세내용

#### (1) 재고 최적 관리하기
**1-1. 자재관리 현황 확인**
- 자재관리 프로그램(SCM)은 원재료 조달부터 최종 소비자까지 공급사슬 전반의 불필요한 요소를 제거해 비용 절감과 고객서비스 수준 유지를 함께 달성하기 위한 시스템이다.
- 도입 배경: 유통·물류 환경 변화, 정보기술 발전, 소비자 욕구 다양화, 기업의 세계화
- 자재수급계획 검토: 판매계획·수주 품목을 기준으로 납기 지연을 막고 과다 재고를 억제하도록 수급량을 산출하고, 검토 결과를 자재수급계획서로 기록한다.
**1-2. 자재 등록**
- 자재 분류란 자재를 일정 기준에 따라 식별·구분하고 품목마다 번호 또는 부호를 부여해 관리 목적에 맞게 체계화하는 것이다.
- 분류 원칙: 점진성(분류 범위를 가감할 여유), 포괄성(모든 품목을 포괄), 이해 용이성(코드만 보고 의미 파악)
- 수행: 품목코드별로 자재를 분류하여 자재관리 프로그램에 등록한다.
**1-3. 자재 보관위치 및 보관환경 결정**
- 수입검사 절차: 검사 준비·실시 → 부적합 자재 별도 보관 및 입출고 통제 → 검사장비 교정·점검 → 불합격 라벨 부착 및 시정조치 → 검사 이력 데이터 관리
- 자재별 품질정보(명칭, 규격, 재질, 제작사 등)를 확인한다.
- 보관 원칙: 보관위치 표시, 분류별 저장, 품질 보존, 선입선출, 공간 활용
- 수행: 품목별 보관위치 및 보관환경을 프로그램에 등록한다.
**1-4. 자재 운반설비 관리**
- 운반설비 종류: 동력식 트럭, 기중기·산업용 모노레일·승강기, 컨베이어, 무인운반차(AGV)
- 수행: 자재 특성과 입출고 흐름에 맞는 운반설비를 결정하고 등록한다.

#### (2) 자재추적 관리하기
**2-1. 자재 입출고 현황 입력**
- 자재소요계획(MRP)은 기준생산일정(MPS)에 따라 제품별 자재 소요량을 산출하고, 리드타임을 고려해 발주 시점을 정하는 방법이다.
- 자재수급계획은 부품구성표(BOM)와 재고 정보를 바탕으로 수립한다.
- 수행: 자재수급계획에 따라 자재 입고·출고 현황을 프로그램에 입력한다.
**2-2. 자재적재 위치 및 수량 파악**
- 자재 유형: 원자재, 부품, 반제품 등 형태에 따라 분류한다.
- 자재번호 부여방식: 일련번호, 블록번호, 그룹번호, 유의숫자, 기호식 등
- 수행: 자재적재 위치와 수량을 프로그램으로 파악한다.
**2-3. 반제품 현황 등록 및 파악**
- 자재 기준정보(자재번호, 품목·규격, 주 저장창고)와 품목 구성정보를 표준화한다.
- 수행: 생산 공정 내 반제품 현황을 등록하고 파악한다.

#### (3) 재고현황 파악하기
**3-1. 재고 파악 및 관리**
- 재고 보유 동기(운영·예방·투기 등)와 재고 관련 비용(자재비, 재고유지비, 재고부족비)을 이해한다.
- 재고유지비에는 보관비용, 재고서비스비용, 재고위험비용, 폐기비용이 포함된다.
- 재고관리 포인트: 보관품목 배치 합리화, 재고 편재 방지, 사장재고 파악
- 수행: 자재 현황 및 자재 회전율을 분석하고 불용·폐기자재 현황을 파악한다.

## [B] 샘플 보고서 3종 (학습자 작성 부분 예시)

### 샘플 1 – 수기 관리로 인한 재고 불일치
- 회사명: (예시) A사 – 금속가공 부품 제조
- 요약문 3. 문제해결 제안: 수기 기록으로 발생한 재고 불일치를 해결하기 위해 입출고 즉시 프로그램 입력, 월말 정기 재고조사, 담당자 교육을 제안하였다.
- 요약문 4. 향후계획: 프로그램 즉시 입력 방식을 회사 입출고 업무에 적용하고 실사 결과로 효과를 확인하겠다.
- Ⅰ-2. 문제해결 경험: 자재 입출고를 수기 장부로 기록하다 보니 기록 누락·오기가 생겨, 시스템 재고와 실물 재고가 맞지 않는 경우가 있었다. 학습한 자재 입출고 현황 입력(2-1)과 재고 파악(3-1) 절차를 적용해 입출고를 프로그램에 바로 입력하고 정기적으로 실사하는 방법을 정리하였다.
- Ⅱ-1-1) 현상: 시스템상 재고와 실제 창고 재고가 일치하지 않아, 생산 투입 시점에 자재가 부족하거나 불필요한 추가 발주가 발생하였다.
- Ⅱ-1-2) 원인: ① 입출고 내역을 수기로 기록한 뒤 나중에 일괄 입력하여 누락·오기가 발생 ② 정기 재고조사(실사) 절차가 없음 ③ 담당자별로 기록 방법이 다름
- Ⅱ-1-3) 개선 방안:
  1) 입출고 즉시 자재관리 프로그램에 입력하여 실시간으로 재고를 갱신한다.
  2) 월말 정기 재고조사로 실물재고와 이론재고를 비교하고, 차이가 나면 원인을 확인해 즉시 수정한다.
  3) 입출고 담당자에게 프로그램 입력 절차를 교육하고 표준 기록 방법을 정한다.
- Ⅱ-1-4) 기대 효과: 재고 정확도가 높아져 자재 부족으로 인한 생산 지연과 불필요한 추가 발주를 줄일 수 있다. (효과 수치는 적용 후 실사 결과로 확인 필요)
- Ⅱ-2. 실무와의 비교: 현재 우리 회사는 입출고를 수기로 기록한 뒤 주 단위로 정리하고 있어 학습한 실시간 입력 방식과 차이가 있다. 프로그램 입력과 월말 실사를 도입하면 재고 불일치 문제를 줄일 수 있을 것으로 판단한다.
- Ⅲ-1. 소감: 자재관리 프로그램을 직접 다뤄 보며 이론으로만 알던 입출고·재고 관리 절차가 실제 업무와 어떻게 연결되는지 이해할 수 있었다. 특히 정확한 재고 기록이 생산 일정에 직접 영향을 준다는 점을 실감하였다.
- Ⅲ-2. 향후 계획: 회사 입출고 업무에 프로그램 즉시 입력 방식을 우선 적용하고, 월말 재고조사 결과를 기록하여 개선 효과를 확인하겠다.

### 샘플 2 – 자재코드 체계 미비로 인한 중복·오등록
- 회사명: (예시) B사 – 전기·전자 부품 조립
- 요약문 3. 문제해결 제안: 자재 중복·오등록 문제를 해결하기 위해 코드 체계 수립, 등록 담당자 지정 및 필수 입력 항목 설정, 기존 중복 코드 통합을 제안하였다.
- 요약문 4. 향후계획: 회사 자재 코드 체계 초안을 만들어 신규 등록 기준부터 적용하겠다.
- Ⅰ-2. 문제해결 경험: 같은 부품이 담당자마다 다른 이름과 코드로 등록되어 재고가 여러 곳에 나뉘어 보이는 문제가 있었다. 학습한 자재 분류 원칙(1-2)과 자재번호 부여방식(2-2)을 바탕으로 코드 체계를 정비하는 방안을 정리하였다.
- Ⅱ-1-1) 현상: 동일 부품이 서로 다른 품명·코드로 중복 등록되어 재고 현황이 정확하지 않고, 잘못된 품목이 출고되는 일이 있었다.
- Ⅱ-1-2) 원인: ① 자재 분류 기준과 코드 부여 규칙이 문서화되어 있지 않음 ② 신규 자재를 누구나 임의로 등록 ③ 규격·단위 정보가 표준화되지 않음
- Ⅱ-1-3) 개선 방안:
  1) 분류 원칙(점진성·포괄성·이해 용이성)에 맞는 코드 체계(대분류-중분류-일련번호)를 정한다.
  2) 신규 자재 등록 담당자를 지정하고, 등록 시 품목·규격·단위를 필수 입력하도록 한다.
  3) 기존 등록 품목을 점검하여 중복 코드를 통합하고, 사용하지 않는 코드는 정리한다.
- Ⅱ-1-4) 기대 효과: 품목별 재고를 한 코드로 정확히 파악할 수 있어 오출고와 중복 발주를 줄일 수 있다. (중복 품목 수 등은 점검 후 확인 필요)
- Ⅱ-2. 실무와의 비교: 현재 회사에는 코드 부여 규칙이 없어 담당자별로 품명을 다르게 입력하고 있다. 학습한 분류 원칙과 번호 부여방식을 적용하면 등록 단계에서부터 오류를 줄일 수 있다.
- Ⅲ-1. 소감: 자재 코드가 단순한 번호가 아니라 재고 정확도와 업무 효율을 좌우하는 기준 정보라는 것을 알게 되었다.
- Ⅲ-2. 향후 계획: 회사 자재 목록을 정리해 코드 체계 초안을 만들고, 관련 부서와 협의하여 신규 등록 기준부터 적용하겠다.

### 샘플 3 – 보관위치 미지정으로 인한 선입선출 실패·자재 탐색 지연
- 회사명: (예시) C사 – 식품 포장재 생산
- 요약문 3. 문제해결 제안: 보관위치 미지정으로 인한 탐색 지연과 선입선출 실패를 해결하기 위해 로케이션 부여, 보관위치·환경 프로그램 등록, 입고일자 표시를 제안하였다.
- 요약문 4. 향후계획: 사용 빈도가 높은 구역부터 로케이션 관리를 적용하고 불용 자재를 주기적으로 점검하겠다.
- Ⅰ-2. 문제해결 경험: 창고 내 자재 보관위치가 정해져 있지 않아 자재를 찾는 데 시간이 걸리고, 먼저 들어온 자재가 남아 장기 재고가 되는 문제가 있었다. 학습한 보관위치·보관환경 결정(1-3)과 적재 위치 파악(2-2)을 적용하는 방안을 정리하였다.
- Ⅱ-1-1) 현상: 출고 시 자재를 찾는 시간이 길고, 선입선출이 지켜지지 않아 유효기간이 지난 포장재가 발생하였다.
- Ⅱ-1-2) 원인: ① 보관위치(로케이션)가 지정·표시되어 있지 않음 ② 입고일자 정보가 자재에 표시되지 않음 ③ 프로그램에 보관위치 정보가 등록되어 있지 않음
- Ⅱ-1-3) 개선 방안:
  1) 창고를 구역·랙·단으로 나누어 로케이션 번호를 부여하고 현장에 표시한다.
  2) 품목별 보관위치와 보관환경(온도·습도 등)을 프로그램에 등록하고, 입고 시 위치를 함께 입력한다.
  3) 입고일자 라벨을 부착하고 먼저 들어온 자재를 앞쪽에 배치하여 선입선출을 지킨다.
- Ⅱ-1-4) 기대 효과: 자재 탐색 시간이 줄고, 선입선출로 장기·폐기 재고 발생을 줄일 수 있다. (탐색 시간 등은 적용 전후 측정 필요)
- Ⅱ-2. 실무와의 비교: 현재는 빈 공간에 자재를 보관하고 위치를 담당자 기억에 의존하고 있다. 학습한 보관 원칙과 로케이션 관리를 적용하면 담당자가 바뀌어도 일정하게 관리할 수 있다.
- Ⅲ-1. 소감: 보관위치와 보관환경을 체계적으로 정하는 것만으로도 재고 손실과 작업 시간을 줄일 수 있다는 점이 인상 깊었다.
- Ⅲ-2. 향후 계획: 자재 사용 빈도가 높은 구역부터 로케이션 표시를 적용하고, 불용·폐기 자재 현황을 주기적으로 점검하겠다.

# 소스5 – 종합프로젝트실습 (현장 제어기기 운영) 자료 (교과목키: 현장제어)

> [B] 샘플 3종은 문체·분량·구성을 참고하는 용도이며, 문장을 그대로 복사하지 않는다.

## [A] 학습모듈 기반 고정 문안

- 교과목: 종합프로젝트실습 (현장 제어기기 운영)

### 요약문 1. 주요 학습내용
- 현장계측기 운영하기
- 입출력장치 운영하기
- 전송기 운영하기
- 구동기 운영하기

### 요약문 2. 학습한 주요 기술 및 능력
- 온도·압력 검출 방법과 신호 전송기 원리를 확인하여 정확한 제어 운영을 할 수 있다.
- 액위·진동 검출 방법과 신호 전송기 원리를 확인하여 정확한 제어 운영을 할 수 있다.
- 입출력목록(I/O List)에 의해 제어기기와 현장기기의 결선 정보를 확인할 수 있다.
- 입출력장치(I/O 모듈, 카드)의 구성을 파악하여 정상상태 여부를 판단할 수 있다.
- 전송기 동작상태를 검사하고, 교정 절차를 파악하여 필요시 조치할 수 있다.
- 액추에이터 매뉴얼에 의해 구동기를 활용하고, 간단한 교정 절차로 조치할 수 있다.

### Ⅰ-1-1) 개요
현장 제어기기의 특성을 파악하여 설정함으로써 제어대상 설비를 안정적으로 운용할 수 있다. (선수학습: PLC, 자동제어 및 시퀀스제어, 센서공학 기본 지식, 공정배관계장도, 디지털공학, 규격집(KSC·ISO·IEC), 계측장비)

### Ⅰ-1-2) 교육 프로세스
- 현장계측기 운영하기: 공정변수와 온도·압력 검출 → 유량·액위·진동 검출
- 입출력장치 운영하기: 기본 운영 및 제어기기 결선 → 기본 구성과 정상상태 이해
- 전송기 운영하기: 전송기 동작과 검사 → 전송기 회로구성과 조치
- 구동기 운영하기: 구동기 동작과 활용 → 구동기 회로구성과 조치

### Ⅰ-1-3) 교육 상세내용

#### (1) 현장계측기 운영하기
**1-1. 공정변수와 온도 및 압력 검출방법**
- 공정변수는 공정의 조작 상태나 물리적 상태를 바꾸는 환경 조건(온도, 압력, 유량, 액위 등)이다.
- 물리량 변환은 검출기(물리량 → 힘·변위·전압·저항)와 신호전송기(1차 신호 → 공기압·전압·전류 신호)로 이루어진다.
- 센서 분류: 물리센서(온도·광·자기 등), 역학센서(길이·변위·압력·하중 등), 화학센서(가스·습도·이온 등)
- 수행: 서미스터 온도센서 특성 실험, 로드셀을 이용한 압력(무게) 센서 특성 실험
**1-2. 유량, 액위 및 진동 검출 방법**
- 측정 대상에서 검출한 물리량을 전기 신호로 변환하는 원리를 이해한다.
- 수행: 액위 검출 실험, 압전형 진동센서를 이용한 진동 검출 및 공진 주파수 확인

#### (2) 입출력장치 운영하기
**2-1. 기본적인 운영 및 제어기기 결선**
- 입출력장치 매뉴얼(LS산전)의 입출력 규격과 기본 배선도를 확인한다.
- 입출력목록(I/O List)에 따라 제어기기와 현장기기를 결선한다.
- 수행: 유접점 출력, NPN·PNP 트랜지스터 출력 회로 구성
**2-2. 기본적인 구성과 정상상태의 이해**
- 기본 유닛·증설 모듈 및 입출력(I/O) 모듈의 구성을 파악한다.
- 수행: CPU 및 입출력 상태, 통신·모드 설정 상태 확인 / 모듈 장착과 분리

#### (3) 전송기 운영하기
**3-1. 전송기의 동작과 검사**
- 전송기 매뉴얼에 따라 신호 도선 연결, 아날로그 입력 모듈과 USB 섀시 구성을 확인한다.
- 수행: 전송기 소프트웨어 설치 후 데이터 전송 상태와 LED(Active) 표시로 동작상태 검사
**3-2. 전송기 회로구성과 조치**
- USB-UART 전송기의 구성과 교정 절차를 파악한다.
- 수행: USB-ISP LED 모드 확인, USB-UART 전원과 외부 전원 분리 절차

#### (4) 구동기 운영하기
**4-1. 구동기의 동작과 활용**
- 컨트롤 밸브: 솔레노이드 흡인력·전류 특성, 쉐이딩 링(AC 솔레노이드 소음 방지), 코일 절연 종류(E·B·H종)
- 액추에이터: 단동·복동 실린더, 양로드·탠덤·듀얼 행정·로킹 등 특수 실린더와 설치 방법
- 수행: 용도에 따른 방향제어밸브 구성, 공기압 실린더의 충격 흡수(쿠션) 원리 이해
**4-2. 구동기 회로구성과 조치**
- 구동기 회로 구성 도면(수동·자동 선택 스위치)과 간단한 교정 절차를 파악한다.
- 수행: 자동 연속 회로, 자동 연속/단속 회로 수정

## [B] 샘플 보고서 3종 (학습자 작성 부분 예시)

### 샘플 1 – 온도·압력 센서 측정값 오차
- 회사명: (예시) D사 – 사출 성형
- 요약문 3. 문제해결 제안: 센서 측정 오차로 인한 불량을 줄이기 위해 교정 주기 설정, 점검표 보완, 허용 오차 기준 수립을 제안하였다.
- 요약문 4. 향후계획: 담당 설비 센서의 교정 주기와 점검표를 만들어 적용하겠다.
- Ⅰ-2. 문제해결 경험: 설비 온도 표시값과 실제 금형 온도가 달라 불량이 발생하는 경우가 있었다. 학습한 온도·압력 검출 원리(1-1)와 전송기 교정 절차(3-2)를 적용해 센서 점검·교정 방법을 정리하였다.
- Ⅱ-1-1) 현상: 온도 컨트롤러 표시값과 휴대용 측정기로 측정한 값이 달라, 성형 조건이 맞지 않아 불량이 발생하였다.
- Ⅱ-1-2) 원인: ① 센서·전송기의 정기 교정 기준이 없음 ② 센서 설치 위치와 배선 상태를 점검하지 않음 ③ 측정값 이상을 판단하는 기준이 없음
- Ⅱ-1-3) 개선 방안:
  1) 센서와 전송기의 교정 주기를 정하고, 교정 절차를 매뉴얼로 작성한다.
  2) 설비 점검표에 센서 설치 상태·배선·표시값 비교 항목을 추가한다.
  3) 기준 측정기와 비교해 허용 오차를 벗어나면 즉시 교정·교체하도록 기준을 정한다.
- Ⅱ-1-4) 기대 효과: 측정 오차로 인한 성형 조건 이탈과 불량을 줄이고, 설비 이상을 조기에 발견할 수 있다. (허용 오차 값은 설비 사양 확인 후 결정)
- Ⅱ-2. 실무와의 비교: 현재 회사는 센서 이상이 생긴 뒤에야 교체하고 있어, 학습한 정기 검사·교정 방식과 차이가 있다. 점검표에 교정 항목을 넣으면 예방 중심으로 관리할 수 있다.
- Ⅲ-1. 소감: 서미스터와 로드셀 실험을 통해 센서 출력이 어떻게 전기 신호로 바뀌는지 직접 확인하면서, 측정값을 무조건 믿기보다 점검이 필요하다는 것을 알게 되었다.
- Ⅲ-2. 향후 계획: 담당 설비의 센서 목록을 정리하고 교정 주기와 점검표를 만들어 적용하겠다.

### 샘플 2 – PLC 입출력 결선 오류·모듈 상태 점검 미흡
- 회사명: (예시) E사 – 자동화 조립 라인
- 요약문 3. 문제해결 제안: PLC 입력 신호 이상 문제를 해결하기 위해 I/O List 갱신 규칙, 센서 타입 확인 체크리스트, 점검 Flowchart를 제안하였다.
- 요약문 4. 향후계획: 담당 라인의 I/O List를 최신화하고 점검 Flowchart를 공유하겠다.
- Ⅰ-2. 문제해결 경험: 설비 개조 후 입력 신호가 들어오지 않아 라인이 멈춘 적이 있었다. 학습한 I/O List 기반 결선(2-1)과 입출력장치 정상상태 확인(2-2)을 적용해 점검 절차를 정리하였다.
- Ⅱ-1-1) 현상: 센서는 동작하는데 PLC에 입력 신호가 들어오지 않아 설비가 정지하고, 원인 파악에 시간이 오래 걸렸다.
- Ⅱ-1-2) 원인: ① I/O List와 실제 결선이 일치하지 않음(개조 후 도면 미갱신) ② NPN·PNP 센서 타입과 입력 모듈 결선 방식 혼동 ③ 모듈 상태(LED, 통신·모드) 확인 절차 없음
- Ⅱ-1-3) 개선 방안:
  1) 설비 변경 시 I/O List와 결선도를 함께 갱신하는 규칙을 만든다.
  2) 센서 교체 시 NPN·PNP 타입과 입력 모듈 규격을 확인하는 체크리스트를 사용한다.
  3) 고장 시 CPU·입출력 LED → 통신·모드 설정 → 결선 순서로 확인하는 점검 Flowchart를 만든다.
- Ⅱ-1-4) 기대 효과: 결선 오류를 사전에 막고, 고장 시 원인 파악 시간을 줄일 수 있다. (정지 시간 단축 효과는 적용 후 기록으로 확인 필요)
- Ⅱ-2. 실무와의 비교: 현재는 경험 많은 작업자에게 의존해 고장을 찾고 있다. 학습한 정상상태 확인 순서를 Flowchart로 표준화하면 누구나 같은 순서로 점검할 수 있다.
- Ⅲ-1. 소감: 입출력 규격과 결선 방식을 매뉴얼로 직접 확인해 보니, 현장에서 감으로 하던 작업에 근거가 생겼다.
- Ⅲ-2. 향후 계획: 담당 라인의 I/O List를 최신화하고, 점검 Flowchart를 작성해 작업자와 공유하겠다.

### 샘플 3 – 솔레노이드 밸브·공압 실린더 동작 불량
- 회사명: (예시) F사 – 포장 설비 운영
- 요약문 3. 문제해결 제안: 실린더 충격·밸브 소음 문제를 해결하기 위해 쿠션 조정, 밸브 점검 기준 수립, 구동기 회로 도면 정비를 제안하였다.
- 요약문 4. 향후계획: 구동기 점검표를 만들고 회로 변경 이력을 도면과 함께 관리하겠다.
- Ⅰ-2. 문제해결 경험: 공압 실린더가 끝단에서 충격을 주거나, 솔레노이드 밸브에서 소음이 나고 응답이 늦는 문제가 있었다. 학습한 컨트롤 밸브·액추에이터 특성(4-1)과 구동기 회로 교정(4-2)을 적용해 점검 방법을 정리하였다.
- Ⅱ-1-1) 현상: 실린더 끝단 충격으로 지그가 손상되고, 솔레노이드 밸브 소음과 동작 지연이 발생하였다.
- Ⅱ-1-2) 원인: ① 실린더 쿠션 조정이 되어 있지 않음 ② AC 솔레노이드 쉐이딩 링 이탈 등 밸브 상태 점검 부족 ③ 수동·자동 회로 구성이 도면과 다르게 변경됨
- Ⅱ-1-3) 개선 방안:
  1) 실린더 쿠션 니들을 조정하고, 용도에 맞는 실린더·설치 방법인지 확인한다.
  2) 솔레노이드 밸브의 소음·온도·응답을 점검 항목에 넣고, 이상 시 교체 기준을 정한다.
  3) 구동기 회로를 도면 기준으로 정비하고, 자동 연속/단속 회로 변경 시 도면을 함께 수정한다.
- Ⅱ-1-4) 기대 효과: 충격·소음으로 인한 부품 손상과 설비 정지를 줄이고, 구동기 수명을 늘릴 수 있다. (효과는 정비 이력으로 확인 필요)
- Ⅱ-2. 실무와의 비교: 현재는 이상이 생긴 뒤 부품을 교체하는 사후 정비 위주이다. 학습한 밸브·실린더 특성을 점검 기준으로 만들면 예방 정비로 바꿀 수 있다.
- Ⅲ-1. 소감: 방향제어밸브 구성과 쿠션 원리를 실습하면서 현장에서 자주 보던 고장의 원인을 이론적으로 이해할 수 있었다.
- Ⅲ-2. 향후 계획: 담당 설비의 구동기 점검표를 만들고, 회로 변경 이력을 도면과 함께 관리하겠다.
